# OS LoRA Studio 기준

목표: **데이터셋 하나를 넣으면 best LoRA 하나가 나온다.** 사용자가 판단할 것은 없다.
대부분의 사용자는 추천된 LoRA를 의심 없이 쓴다. 그래서 추천은 진짜 best여야 하고, 그 근거는
프로그램 안에서 정교하게 계산한다. 화면에는 결과만 보이고 지표 설명은 보이지 않는다.

기능을 더할 때는 아래 다섯 항목 중 어디에 속하는지, 그 항목의 기준을 어떻게 더 잘 지키는지를 먼저 밝힌다.
어디에도 속하지 않으면 넣지 않는다.

## 1. 데이터 — 원클릭 자동 정리

버튼 하나로 정해진 순서대로 끝까지 처리한다. 지우지 않고 `excluded/`로 옮기며, 한 번에 되돌릴 수 있다.

1. 큰 이미지 줄이기 (뒤 단계가 빨라지도록 먼저)
2. 분석 한 번 (얼굴·닮음·중복·흐림)
3. 빼기: 깨진 파일, 다른 사람, 중복, 흐림
4. 크롭 정리: 과다하면 줄이고, 느슨하면 다시 자르고, 부족하면 닮음 좋은 원본에서 자른다
5. 캡션: 없는 이미지만 만든다
6. 증강: 과다하면 정리하고, 부족하면 만든다
7. 다시 분석해서 남은 문제를 한 줄로 알린다

자동으로 빼지 않는 것: "조금 덜 닮음"(각도·조명 차이가 대부분), "얼굴 안 보임", "해상도 작음".
레시피(크롭 ~20%, 화질 변형 ~15%, 얼굴 묘사 없는 캡션 등)는 실험으로 효과가 증명된 것만 바꾼다.

## 2. 학습 — LR 드라이브

LR은 **이익(캐릭터를 배우는 속도)과 비용(유연성을 잃고 다른 프롬프트로 새는 속도)의 비율**로 운전한다.
이익이 크고 비용이 작으면 유지하거나 올리고, 비율이 나빠지면 내리고, 이익이 비용을 못 넘으면 끝낸다.

- 운전은 센서보다 정교할 수 없다. 센서는 100 step마다 렌더 없이 재는 결정적 측정(고정 이미지·노이즈)이어야 하고,
  4번 평가 결과와 같은 방향으로 움직이는지 검증된 것만 쓴다.
  - 이익 센서 후보: 홀드아웃의 얼굴 영역·낮은 노이즈 단계 loss
  - 비용 센서 후보: 누출의 추세 이탈, 프롬프트를 바꿨을 때 예측 변화의 감소, 학습 이미지만 좋아지는 동안의 홀드아웃 상승
- 센서 검증 전에는 **안전 모드**: 검증된 LR(Qwen 2.1 rank 32 = 1e-4)을 상한으로 두고 올리지 않으며, 끝에서 내린다.
- 학습이 무너지면(NaN, loss 폭주) 되돌리고 LR을 절반으로 낮춘다.
- 판단은 노이즈를 안다: 측정마다 노이즈 크기를 계산하고, 노이즈의 2배를 넘는 변화가 연속 두 번일 때만 반응한다.
- ML: 평가 구간마다 (상태, LR, 이익 변화, 비용 변화)가 하나씩 쌓인다. 충분히 쌓이면 LR에 대한 반응 모델을 학습해 규칙을 대체한다.
  실험 큐는 LR을 일부러 바꿔 가며 이 데이터를 모으는 데 쓴다.

## 3. 저장

일정 간격으로 체크포인트를 저장한다. 최종 선택은 4번이 한다.

## 4. 선택 — 학습 후 고정 평가

학습 중의 값싼 측정으로 추천하지 않는다. 학습이 끝나면 후보 3~4개를 고정 평가 세트(각도·표정·옷·장소·화풍·다른 사람,
고정 seed)로 렌더해서 같은 seed끼리 짝지어 비교한다.

- 최소 요건(닮음, 시킨 대로 그리는지, 누출·번짐)을 통과한 후보 중 닮음이 최고와 통계적으로 같은 것들을 동점으로 보고,
  그중 가장 나중 체크포인트를 추천한다.
- 통과한 후보가 없으면 추천하지 않고, 이유를 쉬운 말 한 줄로 알린다("아직 덜 배웠어요" 등).
- 평가에는 이미 쓰는 가벼운 모델만 쓴다(ArcFace, 얼굴 방향, CLIP). VRAM을 더 잡는 판정 모델은 쓰지 않는다.
- 렌더 장수는 재현성 시험(같은 체크포인트를 seed만 바꿔 두 번 평가)으로 결과가 바뀌지 않는 최소값으로 정한다.
- 평가 세트와 규칙에는 버전을 붙인다.

## 5. 규칙 변경

블라인드 비교(step 번호를 가린 렌더)로 사람이 고른 기록과 어긋날 때만 규칙을 바꾼다. 이 도구는 개발용이며
일반 사용자에게는 보이지 않는다. 규칙을 바꾸면 쌓인 기록에 다시 돌려서 나빠지지 않았는지 확인한다.

## 작업 순서

1. 원클릭 데이터 정리
2. 4번 고정 평가 (best의 정답을 만들고, 센서 검증에도 쓴다)
3. 센서 구현과 검증
4. 비율 기반 LR 드라이브
5. ML 반응 모델

## 근거 (2026-10-28 측정)

- 900 step 이후 체크포인트 간 닮음 차이는 대부분 노이즈다(한 번 측정의 노이즈 ±0.026, 렌더 6장).
  번짐·프롬프트 준수·고개 돌림(렌더 1~2장)은 한 번의 측정으로는 신호와 노이즈를 구분할 수 없다.
- 홀드아웃 loss는 개선분의 90%를 500 step 안에 끝내고 얼굴 학습에 둔감하다. 다만 학습 이미지 loss가 계속 내려가는 동안
  홀드아웃이 여러 번 연속으로 오르는 것은 결정적 측정이라 실제 신호다(담대리 v5 2000~2600 step: 닮음은 제자리, 홀드아웃·누출 상승).
- 예전 과적합 사고는 LR 1e-4보다 높을 때(1.5e-4, 3e-4) 났고, 원인은 얼굴에 둔감한 센서(loss 속도)를 보고 LR을 올린 규칙이었다.
